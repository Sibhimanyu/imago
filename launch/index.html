Launch Day: Imago

Imago turns an API response into an interface: paste a URL and it draws the page the data deserves. The app worked; nobody knew it existed. This is the launch, built to keep working without me.

01

Who it is for

Stated narrowly enough that some people are left out.

For

Developers meeting a public JSON API for the first time.

The ten minutes before the first line of code, when the only question is whether the data is any good.

What they do today

Scroll raw JSON in a browser tab or Postman, then write a throwaway page to see the data.

Imago is that throwaway page, drawn for them.

Left out, on purpose

  • Private APIs that block browser apps (CORS)
  • API testing and POSTs. Postman does that well.
  • Non-developers
  • Teams who want a production dashboard

The product, in nine seconds

02

The four jobs

The brief's problem is "nobody knows it exists".

Marketing brings developers in, Pricing answers the first question about any AI tool, PR lets others talk about it, and Community gives the ones who stay a place to talk. Each runs without me.

Job 1

Marketing

The API gallery: one live page per popular free API, found through search. Zoho Catalyst Slate hosts it; Zoho PageSense measures it.

Job 2

Pricing

Free forever with your own key. An optional hosted-AI plan, waitlist only, asks what people would pay. Zoho Catalyst runs the waitlist: a page, a function and a Data Store table.

Job 3

Public relations

A press kit at imago.onslate.in/press: four reels, ready posts, the mascot and a fact sheet, for anyone who wants to write about or share Imago.

Job 4

Community

GitHub Discussions, one tab from the code, seeded with useful threads. Each gallery page links to its API's thread.

ONE SITE FOR ALL FOUR

Everything lives on imago.onslate.in: the app, the gallery (/apis), the press kit (/press) and the waitlist (/waitlist). PageSense measures all of it, the app included.

The trade-off: Imago keeps model keys in the browser, and a script on the same site could read them. The app lets in PageSense's two hosts by name and no other outside script.

04 · Job 2

Pricing: what it costs, and why

The first question about any AI tool: who pays for the AI, and what happens to my key?

Price follows cost. Free where a user costs nothing; paid only where the AI costs money.

Bring your own key, or none

Free forever

  • No server, so a user costs nothing to serve
  • Runs on the user's own free Gemini or Groq key
  • One model call per response shape: an hour of Watch ≈ 360 fetches, one call
  • No key: the basic layout still works

Charging would need accounts, and accounts would mean a server holding people's keys.

Hosted AI · waitlist

₹99 / month draft

For people with no key. Imago would provide the model, which needs a server and costs money on every call. 100 new layouts ≈ ₹40 of model cost (Gemini 3.1 Flash-Lite, ~$0.005 a layout).

Not built. No payment now.

The waitlist, on Zoho Catalyst

A page on the site posts to a Catalyst function that stores each sign-up in the Data Store. It asks:

  • Email, and what you'd use Imago for
  • Do you already have a Gemini or Groq key?
  • Which monthly price would you pay? ₹49 / ₹99 / ₹199 / only free
  • Email me if hosted AI opens
More detail

Linked from the landing page, Settings and every gallery page. Bots that fill a hidden field are dropped; a repeat email is told it is already on the list.

07

What I dropped, and why

Four of the eight jobs, each for a reason specific to Imago.

Partners

Depends on someone else's yes, so the launch doesn't count on it. One listing request is open: Open-Meteo #2155, sent after fixing a licence credit Imago was missing.

Sales

Nothing to sell yet. The waitlist tests demand before anything is built.

Support

Not a separate job. The app explains its own errors, SUPPORT.md covers the rest, and Discussions Q&A takes questions. A help desk like Zoho Desk would hide answers in private tickets.

Marketplace

Developers don't browse marketplaces for a tool like this, and Zoho Marketplace is for Zoho add-ons.
