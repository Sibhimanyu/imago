Launch Day: Imago

Imago turns an API response into an interface: paste a URL and it draws the page the data deserves. The app worked; nobody knew it existed. This is the launch: who it's for, the four jobs it needs, and the things I built that keep working without me.

App: imago.onslate.in API gallery Press kit Community Spent: ₹0
01

Who it is for

Stated narrowly enough that some people are left out.

For

Developers meeting a public JSON API for the first time.

The ten minutes between finding an API and writing the first line of code against it, when the only question is whether the data is any good.

What they do today

Paste the URL into a browser tab and scroll raw JSON, or send it through Postman and scroll it there.

Then, to really see the data, they write a throwaway page they'll delete by evening.

Imago is that throwaway page, drawn for them.

Left out, on purpose

  • Private or internal APIs that block browser apps (CORS)
  • Anyone sending POSTs or running API tests. Postman does that well.
  • Non-developers. You need to know what an endpoint is.
  • Teams who want a production dashboard

The product, in nine seconds

The four jobs

The brief's problem is "nobody knows it exists". Marketing brings developers in, Pricing answers the first question anyone asks of an AI tool, Public relations lets other people talk about it, and Community gives the ones who stay a place to talk. Each runs without me.

Job 1

Marketing

The API gallery: one live page per popular free API, found through search. Zoho Catalyst Slate hosts it; Zoho PageSense measures it.

Job 2

Pricing

Free forever with your own key, and why. An optional hosted-AI plan, waitlist only, asking what people would pay. Zoho Catalyst runs the waitlist: a page, a function and a Data Store table.

Job 3

Public relations

A press kit: four reels with music and sound, ready posts, the mascot and a fact sheet, for anyone who wants to write about or share Imago. At imago.onslate.in/press.

Job 4

Community

GitHub Discussions, one tab from the code, seeded with threads useful before anyone replies. Each gallery page links to its API's thread.

ONE SITE FOR ALL FOUR

Everything lives on imago.onslate.in. The app, the API gallery (/apis), the press kit (/press) and the waitlist (/waitlist) are one site on one address, and PageSense measures all of it, the app included. The trade-off is stated, not hidden: Imago keeps people's model keys in the browser, and a script on the same site could read them. The app lets in PageSense's two hosts by name and no other outside script.

04 · Job 2

Pricing: what it costs, and why

Imago is an AI tool, and the first question anyone asks is who pays for the AI and what happens to their key. The rule: price follows cost.

Bring your own key, or none

Free forever

No server, so a user costs nothing to serve. The model runs on the user's own free Gemini or Groq key, once per response shape (an hour of Watch ≈ 360 fetches, one model call). With no key, the basic layout still works. Charging would need accounts, and accounts would mean a server holding people's keys.

Hosted AI · waitlist

₹99 / month draft

For people with no key who want Imago to provide the model. That needs a server and costs money on every call, so it would be paid. 100 new layouts ≈ ₹40 of model cost (Gemini 3.1 Flash-Lite, ~$0.005 a layout). Not built. No payment now.

The waitlist, on Zoho Catalyst

A page on the site posts to a Catalyst function that stores each sign-up in the Data Store. It collects demand and price data without me:

  • Email
  • What would you use Imago for?
  • Do you already have a Gemini or Groq key?
  • Which monthly price would you pay? ₹49 / ₹99 / ₹199 / only free
  • Email me if hosted AI opens

Linked from Imago's landing page and Settings, and from every gallery page. Bots that fill a hidden field are dropped; a repeat email is told it is already on the list.

Day 5

The model never writes HTML

X · 255/280

The model never writes HTML.

It gets the response's shape and returns a small JSON plan: which fields matter, which component shows each. Imago's own renderer draws it as text. Nothing from an API or a model is treated as markup.

https://github.com/Sibhimanyu/imago

LinkedIn version

A design choice I'd make again: the model never writes HTML.

Imago works out the response's shape (the schema on the right) and sends it
to the model with a short sample of values. The model returns a small JSON
plan: which fields matter and which component shows each one. Imago's own renderer draws
the plan, and every value goes in as text. Nothing from an API or a model is
ever treated as markup.

The code is open: https://github.com/Sibhimanyu/imago

LinkedIn version

The box takes a curl command as well as a URL, straight from an API's docs
or your browser's "Copy as cURL".

Headers go into Inspect → Headers, -u becomes Basic auth, and -G -d
becomes a query string. Headers the browser sets itself (Cookie,
User-Agent) are left out, and Imago tells you which. Headers only last as
long as the tab is open.

Day 10

360 fetches, one model call

X · 183/280

Watching an endpoint every 10s for an hour: ~360 fetches, one model call.

Imago caches each plan by the response's shape. The values change, the shape doesn't, so the plan is reused.

LinkedIn version

Watching an endpoint every 10 seconds for an hour is about 360 fetches and,
if the response keeps the same shape, one model call.

Imago saves each plan under a fingerprint of the response's shape. The
values change and the shape doesn't, so the plan is reused. That makes
Watch cheap enough to leave on, even on a free key.

07

What I dropped, and why

Four of the eight jobs, each for a reason specific to Imago.

Partners

Depends on someone else's yes, so the launch doesn't count on it. One listing request is open at Open-Meteo #2155, sent after fixing a licence credit Imago was missing.

Sales

Nothing to sell yet. The waitlist tests demand before anything is built.

Support

Not a separate job: the app explains its own errors, SUPPORT.md covers the rest, and Discussions Q&A takes questions. A help desk like Zoho Desk would hide answers in private tickets, the wrong shape for open source.

Marketplace

Developers don't browse marketplaces for a tool like this, and Zoho Marketplace is for Zoho add-ons.
