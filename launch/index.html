Launch Day: Imago

Imago turns an API response into an interface: paste a URL and it draws the page the data deserves. The app worked, but nobody knew it existed. This is the launch: who it's for, the three jobs it needs, and the things I built that keep working without me.

Live: imago.onslate.in github.com/Sibhimanyu/imago Free · MIT · open source Spent: ₹0
01

Who it is for

Stated narrowly enough that some people are left out.

For

Developers meeting a public JSON API for the first time.

The ten minutes between finding an API and writing the first line of code against it, when the only question is whether the data is any good.

What they do today

Paste the URL into a browser tab and scroll raw JSON, or send it through Postman and scroll it there.

Then, to really see the data, they write a throwaway page they'll delete by evening.

Imago is that throwaway page, drawn for them.

Left out, on purpose

  • Private or internal APIs that block browser apps (CORS)
  • Anyone sending POSTs or running API tests. Postman does that well.
  • Non-developers. You need to know what an endpoint is.
  • Teams who want a production dashboard

The product, in nine seconds

02

The three jobs

The brief's problem is "nobody knows it exists". These three take a developer from hearing about Imago, to arriving through an API's docs, to getting past their first problem. Each one runs without me there.

1 · Hear

Marketing

Developers hear about it: 14 scheduled Zoho Social posts, then Show HN, dev.to and Reddit on launch day.

2 · Arrive

Partners

Someone with an audience spreads it: a listing in Open-Meteo's README, read by developers checking out a free API.

3 · Stay

Support

People who get stuck or complain are answered in public on GitHub, by pages and forms that work while I'm away.

How the three were chosen

The facts that decided it

  • Free and open source, with no server, so nothing to sell and no sign-up funnel
  • Users are reading an API's docs at the moment they need it
  • The biggest failure is CORS: many APIs refuse browser apps, and a first-time user who hits that leaves
  • Nothing to spend, and everything has to keep working without me

Tools, chosen to fit an open-source project

  • Zoho Social (free plan) schedules the LinkedIn and X run
  • GitHub for support: public issues, forms and saved replies. A private help desk like Zoho Desk would hide the answers, so I didn't use one.
  • No email campaign tool, because developers watch a repo for releases instead

Day 5

The model never writes HTML

X · 255/280

The model never writes HTML.

It gets the response's shape and returns a small JSON plan: which fields matter, which component shows each. Imago's own renderer draws it as text. Nothing from an API or a model is treated as markup.

https://github.com/Sibhimanyu/imago

LinkedIn version

A design choice I'd make again: the model never writes HTML.

Imago works out the response's shape (the schema on the right) and sends it
to the model with a short sample of values. The model returns a small JSON
plan: which fields matter and which component shows each one. Imago's own renderer draws
the plan, and every value goes in as text. Nothing from an API or a model is
ever treated as markup.

The code is open: https://github.com/Sibhimanyu/imago

360 fetches, one model call

Watching an endpoint every 10s for an hour: ~360 fetches, one model call.

LinkedIn version

Watching an endpoint every 10 seconds for an hour is about 360 fetches and,
if the response keeps the same shape, one model call.

Imago saves each plan under a fingerprint of the response's shape. The
values change and the shape doesn't, so the plan is reused. That makes
Watch cheap enough to leave on, even on a free key.

05 · Job 3

Support: people who get stuck, and people who complain

Free and open source, so support happens in public on GitHub. A question answered in an issue answers the next person who searches for it, and a complaint becomes a bug report the fix links back to.

1 · The app explains itself

Each failure says what happened and what to try, for example "This API does not allow browser apps", with the reason and the fix.

2 · SUPPORT.md

Each error the app shows, word for word, with its fix: CORS, unreachable, Fallback, rejected key, Ollama, share links. Linked from the README and the new-issue page.

3 · Issue forms

"The page came out wrong" asks for a Share link, so every complaint arrives with a way to reproduce it. "Something is broken" points to SUPPORT.md first.

What I do

  • Reply to every issue within two days. SUPPORT.md promises it.
  • Five saved replies: CORS, wrong page, key problems, out of scope, a complaint
  • Labels created: wrong page, cors, out of scope
  • Close with the fix: reply with the release number, so the person who complained sees they were heard

Runbook: support.md

06

What I dropped, and why

Five of the eight jobs, each for a reason specific to Imago.

Sales

For a free tool, the "one yes" is Open-Meteo merging the listing, and that's Partners.

Pricing

Free, decided by how it's built: no server means nothing to pay for. Charging would need accounts, and a server holding people's keys.

Marketplace

Developers don't browse marketplaces for this. Zoho Marketplace is for Zoho add-ons, and Product Hunt is a one-day spike.

Public relations

No one writes about a tool with no users. There's a story once Open-Meteo lists it.

Community

A launch with no users has nobody to talk to each other. GitHub issues cover talking to me for now.
